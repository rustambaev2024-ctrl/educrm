# UX Audit v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a new primary color (Spicy Paprika), glassmorphism on surfaces, and a mobile-first pass extending `teacher/attendance.tsx`'s pattern to all 78 pages / 7 roles, then deploy to `staging` for owner review.

**Architecture:** Foundation-first — palette tokens and glass surface styles land once in `src/styles.css` and the base `Card`/`Sheet`/`Dialog`/`Popover` components, so every page picks up the visual change automatically. Then a per-role mobile audit pass (same order as v1: teacher/support-teacher → student/parent → admin → superadmin → director), each task auditing one role's pages against the Davomat pattern and fixing gaps.

**Tech Stack:** React 19 + TanStack Router + Tailwind v4 + shadcn/ui (new-york, Radix, lucide-react). Design tokens live in `src/styles.css` under `:root`/`.dark`. See `docs/superpowers/specs/2026-08-25-ux-audit-v2-design.md` for full rationale (colors, contrast math, glass performance notes).

## Task 1: Palette v2 tokens

**Files:**
- Modify: `src/styles.css:105-220` (`:root` block) and the corresponding `.dark` block

- [ ] **Step 1: Compute contrast for `#E4572E` on white**

Spec requires WCAG AA on `--primary-foreground: #ffffff`. Compute the contrast ratio for `#E4572E`. If it's below 4.5:1, darken to a variant like `#c9481f` following the same "darken until AA" approach v1 used for the emerald primary (documented in the existing `styles.css:134-137` comment). Pick whichever value passes and note the exact hex used — the rest of this task depends on it. Do this by hand (relative luminance formula) or with a quick throwaway Node/Python one-liner; do not guess.

- [ ] **Step 2: Replace `--primary` and dependents**

In `:root`, replace:
```css
--primary: #0e7a57;
```
with the AA-passing paprika hex from Step 1, e.g.:
```css
--primary: #c9481f; /* Spicy Paprika, darkened for AA on white — verify exact value from Step 1 */
--primary-foreground: #ffffff;
```
Update `--ring` (was `#0e7a57`) to match the new `--primary` value — it should track primary as it did before.

- [ ] **Step 3: Re-derive `--accent`/`--accent-foreground`**

These were emerald-derived soft/dark tones (`--accent: #e1f0e9`, `--accent-foreground: #0b4634`). Replace with paprika-derived equivalents: a very light desaturated paprika tint for `--accent` (e.g. `#fbe6de`) and a dark paprika shade for `--accent-foreground` (e.g. `#5c2410`) — same relationship as the emerald pair (light background usable in badges, dark text on top of it, and readable on `--accent` itself).

- [ ] **Step 4: Re-derive `--sidebar-*` block**

Replace the emerald-dark sidebar (`--sidebar: #0a3527`, `--sidebar-primary: #17a06f`, `--sidebar-ring: #2cc98d`) with `Shadow Grey` from the owner's palette:
```css
--sidebar: #2E282A;
--sidebar-foreground: #ffffff;
--sidebar-primary: #E4572E; /* or the AA-adjusted primary from Step 1 */
--sidebar-primary-foreground: #ffffff;
--sidebar-accent: rgba(255, 255, 255, 0.08);
--sidebar-accent-foreground: #ffffff;
--sidebar-border: rgba(255, 255, 255, 0.1);
--sidebar-ring: #E4572E;
```

- [ ] **Step 5: Set `--warn` to amber, verify hue separation from `--primary`**

Current `--warn: #8f5509` is already a dark amber — check whether it's visually distinct enough from the new red-orange primary at a glance. If they read as too similar, shift `--warn` toward `#a66a00` or use `#FFC914`/`#FF9505` darkened for AA (same darken-for-contrast approach as Step 1). Keep `--warn-soft` consistent (lighter tint of whichever value is chosen).

- [ ] **Step 6: Mirror changes in `.dark`**

Find the `.dark` block (search for `.dark {` in `styles.css`) and apply the same primary/accent/sidebar/warn hue shift, using lighter/more saturated variants appropriate for a dark background (do not just reuse the light-mode hex values — check existing `.dark` overrides for the pattern already used for other tokens like `--ok`/`--bad`/`--info` and follow it).

- [ ] **Step 7: Build check**

Run: `npm run build`
Expected: clean build, no CSS/type errors.

- [ ] **Step 8: Commit**

```bash
git add src/styles.css
git commit -m "feat(design): replace emerald palette with Spicy Paprika primary"
```

## Task 2: Glassmorphism on base surface components

**Files:**
- Modify: `src/components/ui/card.tsx`
- Modify: `src/components/ui/dialog.tsx` (content surface)
- Modify: `src/components/ui/sheet.tsx` (content surface)
- Modify: `src/components/ui/popover.tsx` (content surface)
- Modify: `src/styles.css` (add reusable `.edu-glass` utility class if the components benefit from a shared class instead of repeating Tailwind arbitrary values)

- [ ] **Step 1: Add a shared glass utility class**

In `src/styles.css`, near the other `.edu-*` utility classes (search for `.edu-brand-btn` for the existing pattern), add:
```css
.edu-glass {
  background: color-mix(in srgb, var(--card) 72%, transparent);
  backdrop-filter: blur(12px);
  -webkit-backdrop-filter: blur(12px);
  border: 1px solid color-mix(in srgb, var(--border) 60%, transparent);
}

@media (prefers-reduced-motion: reduce) {
  .edu-glass {
    backdrop-filter: none;
    -webkit-backdrop-filter: none;
    background: var(--card);
  }
}
```
Add a `.dark .edu-glass` override if the light-mode `color-mix` values don't read well on dark backgrounds (check visually after Task 1's dark palette lands — likely needs a different transparency percentage since `--card` is dark, not white).

- [ ] **Step 2: Apply to `Card`**

Open `src/components/ui/card.tsx`, find the base `Card` component's className (the root `div` with `bg-card` or similar), add `edu-glass` to the class list alongside existing classes — do not remove existing radius/shadow classes, just add the glass background/border/blur on top.

- [ ] **Step 3: Apply to `Dialog`, `Sheet`, `Popover` content surfaces**

In each of `dialog.tsx`, `sheet.tsx`, `popover.tsx`, find the `*Content` component's root element (the one with `bg-popover` or `bg-background`) and add `edu-glass` the same way.

- [ ] **Step 4: Verify sidebar is NOT glass**

Grep for the sidebar component (`src/components/layouts/` — check `sidebar-layout.tsx` or equivalent) and confirm it does not use `edu-glass` — per spec, sidebar stays opaque for navigation-anchor readability. If it currently forwards through `Card`, make sure it isn't picking up `edu-glass` accidentally.

- [ ] **Step 5: Visual smoke check**

Run: `npm run build`, then start dev server and open any page with cards (e.g. `/admin` or `/teacher`) at both 1440px and 375px widths. Confirm cards show visible translucency/blur against the page background, text remains readable (no contrast regression), and there's no horizontal scroll introduced.

- [ ] **Step 6: Commit**

```bash
git add src/styles.css src/components/ui/card.tsx src/components/ui/dialog.tsx src/components/ui/sheet.tsx src/components/ui/popover.tsx
git commit -m "feat(design): add glassmorphism to Card/Dialog/Sheet/Popover surfaces"
```
