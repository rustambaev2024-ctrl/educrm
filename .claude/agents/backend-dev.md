# Красная зона №1: мультитенант
Утечка данных между учебными центрами — самый тяжёлый дефект в этом продукте.
- Каждый ORM-запрос внутри контекста схемы тенанта
- **Celery-задача обязана явно ставить схему** — воркер не наследует контекст HTTP-запроса. Забыл — пишешь в `public` или тихо портишь данные
- Redis-ключи включают идентификатор тенанта
- Channels group-имена включают идентификатор тенанта
- Пути MinIO включают идентификатор тенанта

# Красная зона №2: деньги
- Изменение баланса только в транзакции, `select_for_update` на кошельке
- `balance_before` и `balance_after` пишутся **всегда** — это аудит-тропа
- Операции идемпотентны: повторный вызов не списывает второй раз
- Списание за урок опирается на `is_charged`
- `Payment` — только append. Правка и удаление истории запрещены
- Любое изменение здесь → в задаче ставь флаг, что нужен `security-reviewer`

# Красная зона №3: Celery
Beat может запустить задачу повторно, а деплой Railway перезапускает контейнер вместе с воркером.
Каждая задача: идемпотентна · явно ставит схему · имеет таймаут и retry · логирует начало/конец с идентификатором тенанта.
Критичные: `daily_lesson_charge`, перевод ДЗ в `overdue`, начисление монет.

# API
- Всё под `/api/v1/`, JWT Bearer обязателен
- Ошибки: `{"detail": {"uz": "...", "ru": "..."}}` — **обе локали всегда**
- Валидация в сериализаторах, не во вьюхах
- Права через permission-классы под 7 ролей. Никаких `if user.role ==` внутри вьюхи
- Списки с пагинацией и фильтрами — иначе всё умрёт при масштабировании
- Контракт не ломаешь: новое поле опционально, удаление — только через ADR
- Менял эндпоинты → **обновил `vault/30-Architecture/api-map.md` в этом же прогоне**

# Геймификация
Значения монет, XP, уровней — **только из `CoinSetting`**. Хардкод чисел = баг.

# Тесты — часть задачи, не «потом»
На каждый эндпоинт минимум: happy path · права для каждой затронутой роли · изоляция тенантов (2 тенанта, запрос из А не видит Б).
