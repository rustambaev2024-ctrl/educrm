# Как запустить систему агентов

## Куда ты пишешь

Одна команда. Больше знать ничего не нужно.

```bash
cd C:\Users\kitsu\Desktop\CRM\educrm-deploy
claude
```
```
/tl учителя жалуются что не сохраняется посещаемость
```

Свободным текстом, своими словами. Дальше тех-лид работает сам:

1. Читает `vault/` — правила, стандарты, состояние
2. Читает `open-issues.md` — **что по этой проблеме уже проверено и исключено**
3. Ищет grep-ом в `src/` и `backend/apps/`, о чём вообще речь
4. Определяет затронутые модули и роли из 7
5. Спавнит нужные роли — независимые параллельно
6. Каждый агент проходит свою разведку: скан кода → vault → веб при сомнении → доустановка MCP/скилла под задачу
7. Пишет спеку, создаёт задачи с зависимостями
8. Отчитывается: что решили, кто первый, что нужно от тебя

## Примеры того, что можно написать

```
/tl переделаем дизайн канбана лидов, сейчас неудобно на мобиле
/tl ускорить логин, он тормозит при росте числа центров
/tl добавить экспорт финансового отчёта в excel для директора
/tl разобраться с дублированием celery, боюсь двойных списаний
/tl группы не показываются у части учителей
```

Тех-лид сам решит, кого поднимать. UI → дизайнер и UX-редактор. Данные → БД-инженер. Деньги → обязательно безопасник.

## Вспомогательные команды

| Команда | Когда |
|---|---|
| `/standup` | Утром: что двигается, что стоит, что нужно от тебя |
| `/work <роль>` | Разбудить конкретную роль: `designer`, `frontend`, `qa`… |
| `/qa` | Запустить тестирование готового на staging |
| `/staging T-012 <sha>` | Подтвердить деплой и разблокировать QA (обычно делает GitHub Action) |
| `/release` | Чек-лист и merge в master |
| `/nazorat` | Аудит: стандарты, процесс, признаки деградации агентов |
| `/vault-sync` | Раз в месяц: свести базу знаний с реальностью кода |

# Что нужно сделать один раз

## 1. Установить Claude Code
```bash
npm install -g @anthropic-ai/claude-code
```

## 2. Закоммитить систему — ТОЛЬКО перечисленные файлы

⚠️ **Не делай `git add -A`.** В репозитории сейчас ~400 файлов CRLF-шума и незакоммиченная чужая работа в `src/`. `git add -A` смешает всё в один коммит.

```bash
cd C:\Users\kitsu\Desktop\CRM\educrm-deploy
git checkout staging

git add vault/ scripts/ .claude/agents/ .claude/commands/ .claude/settings.json
git add .github/workflows/agent-handoff.yml .github/workflows/nazorat.yml
git add CLAUDE.md ЗАПУСК.md

git status          # проверь глазами: только эти файлы
git commit -m "chore: система ИИ-агентов — vault, 10 ролей, движок хендоффов"
git push origin staging
```

## 3. Включить GitHub Actions
Settings → Actions → General → Workflow permissions → **Read and write permissions**

Без этого workflow не сможет записать `staging_commit` и QA не будет разблокироваться автоматически.

## 4. Открыть базу знаний в Obsidian
Obsidian → `Open folder as vault` → выбрать `educrm-deploy/vault/`
Начни с `00-Index/HOME.md`.

Агенты читают те же файлы из репозитория — синхронизация не нужна.

## 5. Первый прогон
```
/standup
```
Покажет пустое состояние — значит всё работает.

# Три правила, без которых система деградирует

**1. Знание — только в vault.** Обсудил что-то важное с агентом в чате → занеси в vault. Нашли причину жалобы → впишите в `open-issues.md`. Иначе через месяц агенты начнут с нуля. Это причина №1, по которой прошлая команда отупела.

**2. Не редактируй `state.json` руками.** Запрещено в настройках. Только через `scripts/state.py` — он валидирует переходы.

**3. Наzorat не участвует в работе.** Не проси его что-то исправить. Наблюдатель, который участвует, слепнет.

# Что стоит решить в первую очередь

Из `vault/30-Architecture/risks.md`, по важности:

1. **R-1: дублирование Celery worker/beat.** Риск двойного списания денег с кошельков учеников при следующем деплое. Нужен ADR о целевой архитектуре
2. **R-11: нет `.gitattributes`.** 400 файлов CRLF-шума мешают и людям, и агентам. Механический коммит с `git add --renormalize .`
3. **R-12: незакоммиченная работа в `src/`.** Реши её судьбу до запуска агентов
4. **И-1: посещаемость не сохраняется.** Жалоба живёт неделю. Главный кандидат — тихий `qs.none()` при отсутствии `staff_profile`
5. **R-2: логин перебирает схемы по номеру телефона.** Прямо на пути масштабирования

Каждый пункт — через `/tl`.
