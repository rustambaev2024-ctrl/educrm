# Открытые жалобы пользователей

> Из диагностики 2026-07-10. **Причины не найдены.** Это не задачи в state.json —
> это входящие проблемы, требующие расследования через `/tl`.

## 🔴 И-1. Посещаемость не сохраняется у части учителей (уже неделю)

**Что проверено и исключено 2026-07-10:**
Гарда «группа должна быть active» в `backend/apps/lessons/views.py` **не существует** — grep по всему репо не нашёл ни в бэкенде, ни во фронте, ни в тестах. Единственные реальные проверки в `attendance()`:
- `lesson.status == "cancelled"`
- лимит бэкдейтинга 14 дней для `teacher` / `support_teacher`

**Значит причина жалобы не в этом.** Кандидаты, требуют проверки в БД:

1. **`hasattr(user, "staff_profile")`** — если у teacher-пользователя нет `staff_profile`, то `get_queryset` **молча** возвращает `qs.none()` без ошибки. Смотреть `backend/apps/lessons/views.py`, `LessonViewSet` / `GroupViewSet`. Самый вероятный кандидат: отказ тихий, пользователь видит пустоту.
2. **Рассинхрон `branch_id`** — `GroupViewSet.get_queryset` для teacher фильтрует и по `branch_id` учителя, и по `teacher=staff_profile`. При переводе учителя между филиалами группа перестаёт быть видна.
3. **Лимит бэкдейтинга 14 дней** мог неожиданно задеть старые уроки.

⚠️ **Не чинить, добавляя гард по `group.status` «для надёжности».** Его никогда не было — это создаст новый баг вместо решения текущего.

## 🔴 И-2. Учитель не видит свою группу в посещаемости
Та же причина, что И-1: `staff_profile` / `branch_id`. Расследовать вместе.

## 🟠 И-3. Группы не показываются
**Не исследовано.** Требует отдельного разбора.
