# Стандарты QA

## Когда QA начинает
**Только** когда задача в статусе `qa` и в `state.json` есть `staging_commit`.
Пока программист не запушил в `staging` и деплой не прошёл — QA **не начинает** и явно сообщает «заблокирован, жду staging».

## Тест-план — структура
1. Затронутые модули (из [[modules-index]])
2. Затронутые роли (все из 7, кого касается)
3. Матрица: **роль × сценарий → ожидаемый результат**
4. Негативные сценарии (нет прав, невалидные данные, обрыв сети)
5. Регресс критических путей
6. Проверка UZ и RU
7. Мобайл, если затронуты student/parent
8. Изоляция тенантов

## Критические пути — регресс всегда
| Путь | Что проверяем |
|---|---|
| Посещаемость | Отметка → монеты начислены **один раз** → списание за урок **один раз** (`is_charged`) |
| Лид → ученик | Конвертация не создаёт дубликат аккаунта при повторном нажатии |
| Кошелёк | `balance_before`/`balance_after` согласованы, отрицательный баланс даёт статус `debtor` |
| Зарплата | `fixed_salary` и `salary_percent` считаются верно, штрафы/бонусы учтены |
| Статус ученика | `expelled`/`archived`/`graduate` закрывает активные членства |
| Бэкдейтинг | Учитель не может отметить посещаемость старше 14 дней |
| Мультитенант | Тенант А не видит данные тенанта Б: API, кэш, WebSocket, файлы |
| Мессенджер | Родитель видит переписку только по своему ребёнку |
| Квиз live | Сессия по 6-значному коду, рейтинг формируется |
| Магазин | Лимиты недели/месяца, минимальный уровень, дни работы |

## Оформление бага
Задача со ссылкой на исходную, с шагами воспроизведения, ролью, тенантом, ожидаемым и фактическим результатом, severity (blocker/critical/major/minor).

## Вердикт
`pass` · `pass with minors` (минорные оформлены как отдельные задачи) · `fail` (возврат в `dev` с конкретикой)
