# Протокол разведки — обязателен для каждого агента

Ты не начинаешь работу с догадок. Ты начинаешь с фактов. Пять шагов, по порядку.

## Шаг 1. Состояние
```bash
python scripts/state.py mine <твоя-роль>
```
Нет задач или задача заблокирована → **останавливаешься** и говоришь, чего ждёшь. Не выдумывай себе работу.

## Шаг 2. База знаний
Читаешь `vault/00-Index/HOME.md`, затем свои стандарты и заметки затронутых модулей.
**Обязательно [[risks]] и [[open-issues]]** — там знания, купленные болью прода. Не повторяй уже проведённое расследование.

## Шаг 3. Разведка по коду — не по документации
Документация врёт. Она уже врала: старый `CLAUDE.md` утверждал деплой из ветки `main`, которой не существует, и перечислял 8 ролей вместо 7.

Прежде чем менять — прочитай, что там на самом деле:
```bash
# где живёт то, что трогаешь
grep -rn "<ключевое-слово>" src backend/apps --include=*.tsx --include=*.py | head -30
# как это уже сделано в 2-3 похожих местах — повторяй существующий паттерн
```
Правило: **найди 2–3 аналогичных места и следуй их паттерну.** Свой стиль в чужом проекте — это техдолг.

Расхождение кода и vault → **правишь vault сразу**. Не «потом».

## Шаг 4. Внешняя проверка — если есть сомнение
Не уверен в API библиотеки, в breaking change, в правильном подходе — **проверь, не угадывай**:
- `WebSearch` — актуальные практики, breaking changes, известные баги
- `WebFetch` — официальная документация
- `context7` MCP — актуальные доки библиотеки прямо в контекст

Особенно важно: **Tailwind v4** и **TanStack Start** свежие, знание по ним могло устареть. Проверяй.

## Шаг 5. Доустановка инструментов
Не хватает инструмента для честного выполнения задачи — поставь. См. [[tooling]].

Примеры, когда это оправдано:
- QA нужно реально проверить экран под 4 ролями и на мобайле → Playwright MCP
- db-engineer расследует жалобу И-1 и нужны данные staging → Postgres MCP (**staging, не prod**)
- devops должен подтвердить, какая ветка задеплоена → Railway MCP
- любой сомневается в API Tailwind v4 → context7

Ставишь только под задачу. Лишний MCP забивает контекст и делает тебя глупее — это ровно та причина, по которой прошлая команда агентов деградировала.

## Чего протокол не разрешает
- Пропустить шаг 1 и начать работу над заблокированной задачей
- Менять код, не прочитав похожие места
- Гадать вместо проверки, когда проверка занимает одну команду
- Ставить MCP «на будущее»
- Трогать прод-БД
