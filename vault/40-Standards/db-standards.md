# Стандарты БД (PostgreSQL / django-tenants)

Контекст: [[multitenancy]] · [[data-model]]

## Миграции
1. Обратимы, либо в PR обосновано почему нет
2. Схема и данные — **разными** миграциями
3. `RunPython` всегда с `reverse_code` (допустим `noop`)
4. Применяются к shared **и ко всем** tenant-схемам. Проверить, что новый тенант тоже получает изменение
5. Порядок применения: **staging → проверка → prod**. Без исключений
6. Изменение `Payment` / `Wallet` / `Attendance` → обязательное ревью `security-reviewer`

## Целостность
- Уникальные ограничения на уровне БД, не только в коде (пример: активное `GroupMembership` уникально)
- Внешние ключи с осознанным `on_delete` — `CASCADE` на финансовых записях запрещён
- Индексы на полях фильтрации и сортировки: даты уроков, статусы, телефон, FK

## Производительность (важно при масштабировании)
- Ловить N+1: `select_related` / `prefetch_related`
- Списки — пагинация обязательна
- Аналитика — агрегаты на стороне БД, не в Python
- Тяжёлые отчёты — в Celery, не в HTTP-запросе

## Красная зона
- `Payment` — только append; правка/удаление истории запрещены
- Массовые `update()` на финансовых таблицах — только с явным ADR
- Никаких деструктивных миграций без документированного бэкапа
