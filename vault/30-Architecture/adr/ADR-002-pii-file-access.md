# ADR-002: Доступ к файлам с PII несовершеннолетних (документы учеников)

- **Статус:** accepted (реализовано в T-013, 2026-07-29)
- **Дата:** 2026-07-29
- **Автор:** tech-lead
- **Консультанты:** security-reviewer (находка R-17, сессия полного аудита F-002)

## Контекст

`Student.file` (`backend/apps/students/models.py:98`) хранит сканы паспортов и свидетельств о рождении детей. Фактическое хранилище — `FileSystemStorage` (`backend/config/settings/base.py:195`), не MinIO, хотя `AWS_*`/`MINIO_*` настройки присутствуют в конфиге — они мертвы, ни один вызов boto3/presigned не найден в коде. Путь загрузки не содержит идентификатор тенанта (нарушение инварианта 5 `multitenancy.md`). `/media/` раздаётся `django.views.static.serve` в проде без аутентификации и без срока жизни ссылки — то есть скан документа ребёнка доступен всем, у кого есть URL, включая через Referer/логи прокси/историю браузера.

Прежняя запись R-9 в risks.md ошибочно описывала это как «PII в MinIO, нужны presigned-ссылки» — по факту кода файлы никогда не были в MinIO. Формулировка исправлена (см. R-17).

## Варианты

### A) Presigned URL через MinIO
Перенести хранение в уже настроенный MinIO, отдавать короткоживущие presigned-ссылки.
Плюсы: соответствует изначальному замыслу инфраструктуры (`MINIO_*` уже в settings), масштабируется, разгружает Django от отдачи файлов.
Минусы: требует миграции существующих файлов с диска в MinIO (одноразовая, но на реальных PII-данных — осторожно), плюс R-5 (ephemeral-диск Railway) до этого момента файлы вообще может терять при редеплое — миграция параллельно чинит и это.
Цена: средняя — новый сервис уже поднят, нужен только код миграции + presigned-генерация.

### B) Proxy-эндпоинт с проверкой прав поверх текущего FileSystemStorage
Оставить файлы на диске, но убрать прямую раздачу `/media/`, завести `GET /api/v1/students/<id>/documents/<doc_id>/` с обычной DRF-permission-проверкой (тот же скоуп, что у `StudentViewSet`) и `FileResponse`.
Плюсы: быстрее в реализации, не трогает хранилище.
Минусы: не решает R-5 (файлы всё ещё на ephemeral-диске, могут пропасть при редеплое), Django-процесс тратит воркеры на отдачу бинарных файлов.
Цена: низкая, но временная — R-5 всё равно потребует миграции на persistent-хранилище позже.

## Решение

**Вариант A (MinIO + presigned).** Обоснование: R-5 (media на ephemeral-диске, файлы периодически 404 после редеплоя) — уже открытый и подтверждённый риск для той же модели `Student.file`. Чинить раздачу файлов вариантом B означало бы через один-два спринта возвращаться к тем же файлам ради R-5 — то есть решать одну проблему дважды. MinIO уже в инфраструктуре (Railway-сервис), настройки в коде уже написаны и просто не подключены — цена подключения ниже, чем строительство параллельного proxy-слоя, который всё равно придётся выбросить.

Путь объекта в MinIO обязан включать `tenant_schema` (устраняет и нарушение инварианта 5 одновременно с R-17).

## Последствия

- **Положительные:** закрывает R-17 (публичный доступ) и R-5 (потеря файлов при редеплое) одной миграцией; путь с тенантом убирает саму возможность коллизии/утечки между центрами на уровне хранения, а не только на уровне прав.
- **Отрицательные:** миграция существующих файлов с реального диска прода — одноразовая операция с PII, требует бэкапа и security-ревью самого скрипта миграции перед запуском. Presigned-ссылки с TTL требуют изменения фронта (компонент, который сейчас рендерит `file.url` напрямую, должен запрашивать свежую ссылку, а не кешировать старую).
- **Что придётся переделать позже:** ничего запланированного — вариант закрывает оба известных риска на этом слое данных.

## Влияние на модули и роли

Модуль: `students` (модель `Student.file`, сериализатор, вьюха). Роли, которые видят документы учеников: `superadmin`, `director`, `branch_admin` (свой филиал), `teacher`/`support_teacher` (если по правам продукта им положено — сверить с `roles-permissions.md` при реализации T-013), `parent` (своего ребёнка). `student` документы не просматривает.

## Как реализовано (T-013, 2026-07-29)

Решение принято в варианте A, но с оговоркой: подключение MinIO сделано
переключаемым (`USE_PRIVATE_S3_DOCUMENTS`), а по умолчанию используется
приватный локальный каталог `PRIVATE_MEDIA_ROOT` вне `MEDIA_ROOT`.
Причина: включать S3-хранилище на проде вслепую, не проверив доступность
MinIO с воркера, — риск потерять загрузки. Флаг включает devops после
проверки бакета; код и путь с тенантом уже готовы и не меняются.

Код: `backend/apps/students/storage.py`, `backend/apps/core/media.py`,
`StudentViewSet.download_document`, миграция `students/0006_alter_studentdocument_file.py`.

**Осталось (не входило в T-013):** скрипт переноса уже загруженных файлов
с диска прода в приватное хранилище с путём, включающим tenant_schema.
Это операция с реальным PII — нужен бэкап и security-ревью самого скрипта.
До переноса старые документы недоступны ни по `/media/`, ни через
download-эндпоинт: ссылка в БД указывает на старый путь.
