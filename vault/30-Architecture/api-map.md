# Карта API

Базовый URL: **`/api/v1/`**. Все эндпоинты требуют JWT Bearer-токен, кроме `/auth/token/` и публичных.
Формат ошибок: `{"detail": {"uz": "...", "ru": "..."}}`

| Путь | Модуль |
|---|---|
| `/auth/*` | Аутентификация (token, refresh, me) |
| `/students/*` | Ученики, лиды, документы |
| `/staff/*` | Сотрудники |
| `/courses/*` | Курсы |
| `/groups/*` | Группы, членства |
| `/lessons/*` | Уроки, посещаемость, cancel, reschedule |
| `/attendance/*` | Посещаемость (CRUD) |
| `/payments/*` | Финансовые операции |
| `/grades/*` | Оценки, экзамены |
| `/homeworks/*` | Домашние задания |
| `/chats/*` | Мессенджер |
| `/notifications/*` | Уведомления |
| `/analytics/*` | Аналитика |
| `/coins/*` | Геймификация |
| `/quizzes/*` | Квизы |
| `/superadmin/*` | Управление платформой |

## Пагинация списков (T-018 / R-24, 2026-07-29)

`DEFAULT_PAGINATION_CLASS = apps.core.pagination.OptInPageNumberPagination` включён глобально.

- Клиент прислал `?page=` или `?page_size=` → ответ `{count, next, previous, results}`.
  `page_size` по умолчанию 100, максимум 1000.
- Клиент ничего не прислал → прежний плоский массив, но **не более 1000** записей
  (жёсткий потолок против 39-килобайтных ответов, R-6).
- Исключения со своей пагинацией: `/students/` (`StudentPagination`, всегда постранично)
  и `/chats/*/messages/` (курсорная).

### Признак усечения (T-028, 2026-07-31)

Непагинированный ответ, упёршийся в потолок, помечается **заголовками** — тело
остаётся плоским массивом, контракт не ломается:

| Заголовок | Когда | Значение |
|---|---|---|
| `X-Result-Truncated` | только при усечении | `true` |
| `X-Result-Limit` | только при усечении | текущий потолок (`1000`) |

- Ровно `MAX_UNPAGINATED` записей усечением **не** считается (проверка идёт по
  выборке `limit + 1`, лишнего `COUNT(*)` нет).
- Пагинированный ответ (`?page`/`?page_size`) заголовков не получает — там есть `count`/`next`.
- Заголовки перечислены в `Access-Control-Expose-Headers` (`apps/core/middleware.py`),
  иначе браузер не отдал бы их фронту при кросс-доменном запросе.
- Усечение пишется в лог уровня `warning` со схемой тенанта и путём.
- **Для фронта:** увидев `X-Result-Truncated: true`, нужно перечитать список
  постранично (`?page=`), а не показывать неполные данные молча.

**Почему opt-in:** фронт (`src/lib/data/store.tsx`) читает постранично только
`/students/`, `/staff/`, `/parents/` (`fetchAllPages`). Безусловный `PAGE_SIZE` молча
обрезал бы группы, уроки, посещаемость, платежи и оценки до первой страницы.
Полное принудительное включение — после миграции фронта (follow-up, роль frontend).

## Уточнения по отдельным эндпоинтам

### `POST /api/v1/payments/trigger-daily-charge/` — ручной запуск списания за уроки
- Права: `IsBranchAdmin` (superadmin · director · branch_admin). Остальные роли — 403.
- **С 2026-07-29 (T-009 / R-22) работает асинхронно и только в схеме текущего тенанта.**
  Раньше вызывал `daily_lesson_charge()` синхронно, а та итерирует все схемы платформы —
  один POST списывал деньги во всех учебных центрах.
- Ответ: `202 Accepted`, тело `{status:"queued", message, schema, task_id, charges_today}`.
  `charges_today` — количество списаний, уже сделанных сегодня на момент запроса
  (задача выполняется в фоне, итог в ответе не отражается).
- Вызов из схемы `public` → `400` с `{detail:{uz,ru}}`.

### Документы учеников — PII несовершеннолетних (T-013 / R-17, ADR-002)
- **`/media/student_docs/...` больше не отдаётся.** `/media/` раздаётся через
  `apps.core.media.protected_media_serve`, который 404-ит этот сегмент пути.
  Логотипы, аватары, файлы ДЗ отдаются как раньше.
- Новый эндпоинт: `GET /api/v1/students/<id>/documents/<doc_id>/download/`.
  Права — те же, что у `StudentViewSet` (роль + филиал + схема тенанта).
  Ответ: `302` на короткоживущую presigned-ссылку (MinIO, TTL
  `DOCUMENT_URL_TTL_SECONDS`, по умолчанию 300 с) либо файл потоком
  (локальное приватное хранилище).
- `documents[]` в `GET /students/<id>/` больше **не** содержит `file`
  (постоянный публичный URL); вместо него `download_url`. **Ломающее для фронта.**
- `POST /students/<id>/documents/` возвращает `download_url`, поле `file` write-only.
  Валидация загрузки: расширения `pdf/jpg/jpeg/png/heic/webp`, максимум 10 МБ,
  иначе `400 {detail:{uz,ru}}`.
- Путь хранения: `<tenant_schema>/student_docs/<student_id>/<uuid><ext>` —
  тенант в пути (инвариант 5 multitenancy.md), оригинальное имя файла не сохраняется.
- Настройки: `PRIVATE_MEDIA_ROOT`, `USE_PRIVATE_S3_DOCUMENTS`, `DOCUMENT_URL_TTL_SECONDS`.
- **Не сделано в этой задаче:** перенос уже загруженных файлов с диска прода
  в приватное хранилище — одноразовая операция с реальным PII, требует бэкапа
  и security-ревью скрипта (см. ADR-002 «Последствия»). До переноса старые
  документы недоступны ни по `/media/`, ни через download-эндпоинт.

### Живой квиз — анонимные эндпоинты (T-010 / R-19, 2026-07-29)
- `GET /api/v1/quiz-sessions/by-code/<code>/` — ищет сессию **только в схеме тенанта
  запроса** (`X-Tenant-Schema`/домен). Перебор всех схем платформы удалён.
  Ответ дополнен полем `join_ticket` — подписанный тикет со схемой и кодом.
- `POST /api/v1/quiz-sessions/<id>/join/` — принимает опциональное поле `ticket`.
  Если тикет есть, схема берётся из него; `?schema=` больше не читается нигде.
  Ответ дополнен `ws_ticket` для подключения к WebSocket.
- Оба эндпоинта под троттлингом `quiz_join` (30/min, `DEFAULT_THROTTLE_RATES`).
- **Резолв тенанта (фикс Б-1, 2026-07-29).** Оба пути анонимные, но **тенантные**:
  `HeaderOrDomainTenantMiddleware` резолвит тенанта для них штатно
  (`X-Tenant-Schema` → домен) через `TENANT_OPTIONAL_PATH_PREFIXES` /
  `TENANT_OPTIONAL_PATH_PREFIX_SUFFIX`. В `PUBLIC_PATH_*` их быть не должно:
  там `request.tenant = None` ставится **до** резолва, и оба эндпоинта отдавали
  404 всегда. Если тенант не резолвится — ответ `404 {"error": "Session not
  found"}` (не 401: аноним не должен получать ответ про пользователей, а разница
  статусов снова стала бы оракулом имён схем, BUG-037).
- Замороженный/архивный тенант: `POST .../join/` теперь попадает под общий гард
  `_is_blocked_tenant_request` → `403`. Раньше путь был публичным и гард его не
  видел. Поведение намеренное: центр в статусе `frozen`/`archived` не должен
  принимать новые PII детей. `GET by-code` (не мутирующий) не затронут.
- WebSocket `ws/quiz/<code>/`: схема из JWT (`?token=`, хост) или из `?ticket=`.
  Legacy `?schema=` принимается, только если сессия с этим кодом действительно
  есть в этой схеме. Имя группы теперь `quiz_<schema>_<code>`.
- **Follow-up (frontend):** `src/routes/join.tsx` должен передавать `join_ticket`
  в `join`, а `src/routes/play.$code.tsx` — подключаться с `?ticket=<ws_ticket>`
  вместо `?schema=`. До этого работает legacy-путь.

### Пароли (T-015 / R-23, 2026-07-29)
- `AUTH_PASSWORD_VALIDATORS` включены: минимум 8 символов, не только цифры,
  не из списка распространённых, не похож на данные пользователя.
  Слабый пароль → `400` `{detail:{uz,ru,rules}}`.
  **Ломающее для клиента:** пароли уровня `secret123` больше не принимаются.
- `POST /api/v1/staff/` без поля `password` возвращает в ответе новое поле
  `generated_password` — криптостойкий временный пароль (показать один раз).
  Дефолтного `ChangeMe123` больше нет нигде.
- `POST /api/v1/students/` уже возвращал `generated_password`; добавлено
  `parent_generated_password` для впервые созданного родителя.
- Новое поле `must_change_password` в `GET /api/v1/auth/me/` и в `UserSerializer`.
  Ставится в `true` при генерации пароля системой и при админском сбросе
  (`/auth/reset-password/`, `PATCH /staff/` чужого пароля), снимается только
  самостоятельной сменой через `/auth/change-password/`.
  **Принудительная блокировка API до смены пароля пока НЕ включена** — требует
  экрана на фронте, иначе сотрудник с временным паролем окажется заперт.
  Follow-up: frontend + включение гарда.

### `PATCH /api/v1/staff/<id>/` — пароль сотрудника
- Поле `password` доступно: superadmin — всем; себе — всегда; director — всем,
  кроме других director/superadmin; branch_admin — только teacher/support_teacher
  своего филиала. Иначе `403` `{detail:{uz,ru}}` (T-014 / R-18).

### `PATCH /api/v1/homeworks/submissions/<id>/` — статус сдачи ДЗ
- Роль `student` может писать только `status="submitted"`, `answer_text`, `answer_file`.
  Попытка передать `grade`/`teacher_comment` или иной статус → `403` `{detail:{uz,ru}}` (T-008 / R-20).
- `teacher` / `support_teacher` — полный набор полей проверки, без изменений.

## Правила изменения API
- **Не ломать контракт.** Клиент в продакшене. Новое поле — опционально; удаление поля — только через ADR и депрекейшен.
- Версионирование в пути. Ломающее изменение → `/api/v2/`, а не тихая правка v1.
- Каждый новый эндпоинт документируется здесь **в том же PR**.
