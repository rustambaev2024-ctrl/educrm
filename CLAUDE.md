# EduCRM — инструкции для агентов

Мультитенантная платформа управления учебными центрами.
**Продакшен с реальными данными реальных учебных центров.** Ошибки стоят денег и доверия.

Репозиторий: `https://github.com/rustambaev2024-ctrl/educrm`
Владелец проекта — **не программист** и не хочет вникать в технику. Все отчёты ему — простым языком, без имён файлов и технических терминов, если он сам не попросил подробностей.

---

## Главное правило: соразмеряй усилие с задачей

Большинство запросов — маленькие: одна кнопка, один текст, что-то не отображается, мелкая правка. **Чини их сам, за один заход, без созыва других агентов, без вопросов человеку, без задач в `scripts/state.py`.** Это не бюрократический процесс — это инструмент на случай, когда он реально нужен.

Полный процесс с несколькими специалистами, спеками и статусами — только для по-настоящему больших многоэтапных вещей (новая функция с нуля, что-то что трогает деньги/права/данные многих учеников). Такое встречается редко.

Если сомневаешься в размере — считай задачу маленькой и начинай чинить. Подробности: `.claude/agents/tech-lead.md`.

## Как отвечать человеку
Три предложения: что было не так (по-человечески) → что теперь → нужно ли что-то от него.
Не показывай код и названия файлов, если не попросил. Не спрашивай технические уточнения — сам находи ответ в коде.

## Три правила

### 1. Важное — в vault, не только в чат
Нашёл причину давней проблемы или узнал что-то, что стоит помнить надолго — коротко впиши в подходящий файл `vault/`. Не превращай это в ритуал на каждую мелочь.

### 2. Разведка по коду, не по документации
Документация здесь уже врала: старый файл инструкций указывал ветку `main`, которой нет, и 8 ролей вместо 7. Проверяй в коде, не верь написанному на слово.

### 3. Состояние больших задач — только через CLI
Если используешь `scripts/state.py` (для больших многоэтапных вещей) — не редактируй `vault/60-State/state.json` руками, только через сам скрипт.

## Технические факты (для себя, не для пересказа человеку)

**Ветки:** `master` — продакшен, реальные данные, прямой пуш запрещён, только merge из `staging`. `staging` — тестовое окружение. Ветки `main` не существует.

**Стек:** Django 4.x + DRF · PostgreSQL + `django-tenants` · Redis · Celery worker+beat · Django Channels · MinIO · Daphne. React 19.2 · TypeScript · TanStack Router + Start · Tailwind v4.2 · Vite 7.3 · Radix + shadcn/ui · `lucide-react` · `sonner`.

**Структура:** `backend/apps/` (18 приложений) · `src/routes/` (страницы по ролям) · `src/lib/api.ts` (все обращения к серверу).

**7 ролей** (подтверждено по `backend/apps/accounts/models.py`): `superadmin` `director` `branch_admin` `teacher` `support_teacher` `student` `parent`. Папка `src/routes/admin/` — это на самом деле роль `branch_admin`, имя папки историческое.

**Три зоны повышенной осторожности:**
1. Мультитенант — запрос вне схемы тенанта = утечка данных между учебными центрами. Celery-задачи обязаны явно ставить схему.
2. Деньги — `balance_before`/`balance_after` не трогать напрямую, операции должны быть идемпотентны (не списывать дважды).
3. Личные данные детей — в карточках учеников паспорта и свидетельства о рождении.

**Техдолг — храповик, не запрет.** `python scripts/baseline.py check` — если используешь, следит, чтобы старый беспорядок (хардкод цветов, `any` и т.п.) не увеличивался. Новый код старайся писать чище, старый трогать не обязательно.

**Проверка перед сдачей крупной задачи:**
```bash
npm run build
python manage.py check
```
`python manage.py migrate` агентам запрещён — миграции на прод применяет человек.

**Двуязычность:** если задача про текст в интерфейсе — каждая строка должна быть и на узбекском, и на русском.
